The problem

The hard part of a support agent is not the conversation.

Support is where most companies first put an LLM in front of customers. A bot that only talks is a search box. The value is in acting: cancel, redirect, refund.

The risk is the same thing. Software that can be talked into things is now touching money.

The model decides what to do.
Code decides whether it is allowed.

  • The model never types a refund amount.
  • Windows, final sale, ownership: checked in the tool.
  • Over £100, the run stops and a person decides.
  • Every step is on screen and in an audit log.

Architecture

One loop, seven tools, three outcomes.

Agent loopClaude Opus 5, adaptive thinking, prompt caching, strict tool schemas. Max 12 calls.
→
tools.pyThe only code that touches the database. Every business rule lives here.
→
okResult goes back to the model.
refusedThe rule, in words, as a tool error. Final.
needs approvalState saved to SQLite. Loop exits. Resumes on a decision.
  • No amount parameter. issue_refund(order_id, skus, reason). There is no number for an injection to change.
  • A hand-written loop, on purpose. It must stop mid-turn, wait days, and resume from a database row in another process.
  • Same error for "missing" and "not yours". Order numbers cannot be probed.
  • Customer text is data. The prompt says why; the evals attack it.
Evaluation

Pass means the database is right, not that the reply sounds right.

Layer 1 · rules, no model. Nine tests, run in CI on every push. Over-limit refunds pay nothing until approved. Windows and final sale hold. An item is refunded once. Someone else's order looks exactly like a missing one.

Layer 2 · behaviour, live model. 18 scripted conversations, each on a fresh database: lookups, actions, policy refusals, approvals (approved and declined), attacks, escalations.

A scenario passes only if all of these hold:

  • the right tools were called, and no write tool when only reading was needed
  • the database ended in the expected state: exact refund totals, order status, address, ticket priority
  • an approval was, or was not, requested
  • a judge model confirms the reply told the customer the truth

Layer 2 is built but has not been run yet, so no pass rate is claimed. Screenshots in this deck are from demo mode: scripted model turns, real tools, real rules, real approval pause.
